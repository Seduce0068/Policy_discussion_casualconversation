## 概要

シェル言語ごとに AI エージェントのコマンド誤り率を実験し、算出した。
対象はこの環境で利用可能な bash / zsh / nushell / dash の4つ。
各シェルに同一の15問を出題し、隔離環境での実行結果を期待出力と比較した。

結果は bash 0%、zsh 0%、dash 6.7%、nushell 20% である。
標本は各15問・同一エージェント1体・同一モデルであり、
「モデル一般の能力」ではなく、この条件下での観測値として解釈する。

## 実験方法

### 対象シェル

`date` で確認した実験開始時刻は `2026-11-23T13:37:15+09:00` である。
利用可否は `command -v` で確認した。

| シェル | バージョン | 実験対象 | 備考 |
| --- | --- | --- | --- |
| bash | 5.3.9(1)-release | はい | `--noprofile --norc` で起動 |
| zsh | 5.9 | はい | `-f` で起動 |
| nushell | 0.117.0 | はい | `--no-config-file` で起動 |
| dash | (Ubuntu 標準) | はい | POSIX sh 準拠 |
| sh | /usr/bin/dash への symlink | いいえ | dash と同一エンジンの重複 |
| fish, ksh, tcsh, csh, pwsh ほか | 未インストール | いいえ | 実測不可 |

### 出題内容

代入・文字数、配列/リストの要素数、ループ、文字列置換、空文字判定、
終了コード判定、整数合計、空白入りファイル名、インデックス参照、環境変数、
カンマ分割、数値比較、行数カウント、要素の2倍化、小文字化の15問。
各問に期待出力を明示し、エージェントには対象シェル向けのコマンドのみを書かせた。

### 安全策

「安全第一」の指示に従い、次の制約を適用した。

- 子エージェントには**生成のみ**を担当させ、実行・変更・外部送信を禁止した。
- 生成コマンドは危険パターン（rm / sudo / curl / wget / dd / mkfs / chmod / chown /
  kill / pkill / shutdown / reboot / mv / cp など）で事前検査し、該当すれば実行しなかった。
- 実行は `/tmp/shell-mistake-exp.ys5jwV` 配下の隔離ディレクトリに限定し、
  検証用の `a b.txt` と `data.txt` のみを置いた。
- 各コマンドに `timeout 5s` を適用し、シェルの設定ファイル読み込みを無効化した。
- ホストの作業リポジトリ、システム設定、ネットワークへの変更は行わなかった。
- 上記の検査はブラックリスト方式であり、安全性を保証するものではない（「限界」を参照）。

### 採点基準

期待出力と標準出力を厳密に比較し、一致すれば正解とした。
末尾改行はコマンド置換により除去して比較した。
構文エラー・出力不一致・タイムアウト・危険パターン検出はすべてミスに算入した。
判定は stdout のみに行い、終了コードはタイムアウト検出にのみ使用した。
ミス5件については正解可能な代替コマンドを実機で確認し、
出題側の誤り（そのシェルでは実現不能）ではないことを検証した。

## 結果

### 集計

| シェル | 正解 | ミス | ミス率 |
| --- | ---: | ---: | ---: |
| bash | 15/15 | 0 | 0% |
| zsh | 15/15 | 0 | 0% |
| nushell | 12/15 | 3 | 20% |
| dash | 14/15 | 1 | 6.7% |
| 合計 | 56/60 | 4 | 6.7% |

### ミス項目の詳細

| シェル | 問題 | 生成されたコマンド | 実際の結果 |
| --- | --- | --- | --- |
| nushell | Q6 終了コード | `^false; if ($env.LAST_EXIT_CODE != 0) ...` | 出力なし |
| nushell | Q11 カンマ分割 | `"a,b,c" \| split "," \| get 1` | 出力なし |
| nushell | Q14 2倍化 | `[10 20 30] \| each { \|x\| print ($x * 2) }` | `empty list` が余分 |
| dash | Q11 カンマ分割 | `IFS=,; set -- a,b,c; printf ...` | 出力なし |

正解例（親が実機で確認）:

- nushell Q6: `let r = (^false | complete); if ($r.exit_code != 0) { "failed" }`
- nushell Q11: `"a,b,c" | split row "," | get 1`
- nushell Q14: 戻り値を `str join` するか、出力後に `ignore` を付ける。
- dash Q11: `word="a,b,c"; IFS=,; set -- $word; printf '%s\n' "$2"`

POSIX 系の bash と zsh は15問すべて正解した。
dash は IFS の展開タイミングに関する1問のみミスした。
nushell は3問ミスし、いずれも POSIX 系とは異なる構文・データモデルに起因している。

## 考察

POSIX 系シェル（bash / zsh / dash）は、この問題セットでは観測された誤り率が低かった。
ただし dash の Q11 は「IFS を設定してもリテラルの `a,b,c` は分割されない」という
POSIX の細部であり、POSIX 系でも油断ならないことを示している。

nushell のミスは、パイプラインの戻り値が構造化データとして扱われる点、
`split` ではなく `split row` を使う点、終了コードの取得方法が異なる点に集中した。
学習データが POSIX 系に偏っている可能性が考えられるが、
これはこの実験から直接導ける推測であり、確証はない。

統計的には、Wilson 95% 信頼区間は bash / zsh が 79.6〜100%、
dash が 70.2〜98.8%、nushell が 54.8〜93.0% と重なっている。
bash と nushell の Fisher 正確検定（両側）の p 値は 0.224 である。
したがってこの標本数では、シェル間の誤り率に有意差があるとは言えない。
上述の差は記述的な観測値であり、パイロット結果として扱う。

## 限界

- 各シェル15問、同一エージェント1体、同一モデルの1回きり。反復・無作為化なし。
- 出題セットは実験者が選んだものであり、実運用のタスク分布を代表しない。
- エージェントのモデル名・推論設定はデフォルト経路に委ねており、
  他モデルでの再現性は未検証である。
- 採点は stdout 文字列のみ。末尾改行を除去して比較し、
  終了コードはタイムアウト検出のみ、stderr は判定に使っていない。
- 危険パターン検査はブラックリスト方式であり、全ての危険コマンドを検出しない。
  `safe: true` は「既知の危険パターンが見つからなかった」意味であり、保証ではない。
- 隔離は一時ディレクトリへの cd と `timeout 5s` であり、
  コンテナや chroot による隔離ではない。コマンドはホスト権限で実行された。
- 複数行コマンドと同一 id の重複は想定せず、回答の先頭行のみを抽出した。
  今回の全回答は単一行だった。
- fish / ksh / pwsh などは未インストールのため実測していない。
- 生データは `/tmp/shell-mistake-exp.ys5jwV` に一時保存しており、永続保証はない。

## オーケストレーション設定

swarm-limited の制限プロファイルを適用した。

| 項目 | 値 |
| --- | --- |
| 対象スキル | swarm-research |
| 同時起動数の上限 | 6 |
| 実際の同時起動数 | 最大4（R2 のシェル別エージェント） |
| 深度 | 1 |
| トータル起動数 | 参考値 5（R2 が4、R4 が1。制限なし） |
| 推定コスト | 未確認 |
| 停止理由 | ゴール完了（R1〜R6 完了） |

使用モデルは子エージェントのデフォルト経路（親のモデルをフォールバック）である。
R2 で4エージェントを並列起動し、R3 で同じエージェントに追加5問を出題、
R4 で別エージェントが採点を敵対的にレビューした。
子の報告は仮説として扱い、ミス項目は親の実機実行で事実確認した。
