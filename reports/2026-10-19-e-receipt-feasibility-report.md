## 1 Executive Summary

ユーザーの仮説「コンビニの電子レシート導入はそう難しいものでも
ないはず」を検討した結果、以下のような評価に至った。

- **技術的難易度**: 低い。既に実証済みのソリューション
  (スマートレシート: 18,000 店 / 3 億枚) が存在し、JDLA 標準スキ
  ーマ・経産省標準規格も検証済み。
- **普及成立条件**: 高い。技術的なハードルでなく「opt-in 率を上
  げる UX」「FC 加盟店との POS 改修合意」の 2 点に依存する。
- **実装非対称性**: セブン / ファミマ / セコマは 1〜3 か月、ロー
  ソンは 3〜6 か月、ミニストップは対応済み。

ユーザーの仮説はほぼ正しいが、修正が必要なのは
「実装は容易である」ことを示すだけでなく「普及が成立するか」の
非対称性を明確にすることである。

## 2 背景

紙レシートの完全廃止を目的とした本事業では、既に以下の実装事例と
標準仕様が存在する。

- **スマートレシート** (東芝テック): 18,000 店以上で稼働、累計 3
  億枚。
- **経産省標準規格**: KDDI 総研 (2018) の実証実験で検証済み
  (27 店舗 / 2,700 人)。
- **東芝テック国際標準仕様**: フォーマット対応実証済み (2017)。

このうちセブン・ローソン・ファミマ・セコマの 4 チェーンは、既に
会員アプリ／電子マネー決済／ポイントカード提示の UI 骨格を持つ。
購買明細の表示機能だけが未実装という構造であり、新規に車輪の再発
明をする必要はない。

## 4 技術的難易度の評価

### 4.1 難易度の評価が低い理由

- トランデータは既に POS 上で電子データとして存在する。
- 会計ナレッジの同一化 (決済 ID = 会員 ID) が可能で、UX 上の操
  作は「提示 1 回」に圧縮できる。
- 会計時にアプリを見せる opt-in 型と決済時の提示は統合可能で、
  **別々の押下操作を減らせる**。

### 4.2 難易度の評価が高い理由

- FC 加盟店側の POS 改修費用負担が正義と乖離する
  「本部の利益／加盟者の費用」の不均衡。
- opt-in 率が伸びきらない場合の二重インフラ固定費
  (Air レジの前例)。
- 現金決済側の ID 接続 (本部側データ集約を維持するオプション) が
  矢面に現れた場合の法的課題。

## 6 統合アーキテクチャ (ADR-001 要約)

以下の 6 決定事項は ADR-001 (D-1〜D-6) で定義し、このレポートは
要約のみを扱う。

1. **D-1 共通 ID レイヤの採用**: チェーン横断の許可制御・蓄積層
   を用意し、各チェーンの既存会員 ID を紐付ける。
2. **D-2 JDLA 標準フォーマットの採用**: 相互運用実績のあるスキー
   マを採用。
3. **D-3 決済 ID = 会員 ID の統合**: 会計時の提示操作を 1 回で
   完結させる。
4. **D-4 紙の UI 再現と既存インフラの併存**: opt-in とし、紙レ
   シートは原則残存。
5. **D-5 既存アプリへの画面追加**: 新規アプリを作らない。
6. **D-6 センター (中央ゲート) の構成**: チェーン中立の引き離し
   型ゲートとして設計する。

## 7 ロードマップ (Phase 0〜3) と外部放出の定義

### 7.1 Phase 一覧

| フェーズ | 期間 | 内容 |
| --- | --- | --- |
| Phase 0 | 4 週間 | センターの骨格構築・JDLA スキーマの来歴記録 |
| Phase 1 | 8 週間 | セコマ・ファミマ実装 (Pecoma / FamiPay) |
| Phase 2 | 12 週間 | セブン・ローソン実装 + FC 加盟店合意プロセス |
| Phase 3 | 12 週間以上 | opt-in 率 KPI 評価と紙廃止の判断 |

### 7.2 「Phase 2 を外側に放出する」の技术正確な定義

Phase 2 は、本部側アプリの画面追加 (Phase 2a) と、
FC 加盟店側 POS 改修の合意収集 (Phase 2b) に分解される。

| サブフェーズ | 内容 | 主体 | 工程の性質 |
| --- | --- | --- | --- |
| Phase 2a | 本部側アプリ内の「電子レシート」表示 UI 生成 | 本部開発部門 | 技術 |
| Phase 2b | FC 加盟店側の POS 改修同意・fee 配分合意の取得 | 本部 × 加盟店間の契約調整 | 契約 |

Phase 2a が完了しないと Phase 2b は開始できない
(**一方向の依存**を持つ)。この分解明示は、技術工程と契約工程
の**責任境界**をはっきりさせ、「ばかげた表明を排除し、保守可
能なロードマップにする」の意図を持つ。

**「Phase 2 を本部側の内部開発から外部 (加盟店側プロセス) に放
出する」という表現の正確な意図**:

- 実装着手を、本部の IT・アプリ開発部門から **チェーン横断の
  FC 契約調整プロセス**に放出する。
- これは「外部ソリューションにアウトソーシングする」意味では
  **ない**。
- より正確な表現は「**Phase 2 を契約主体の調整へ移す**」である。

### 7.3 Phase 2a / 2b の依存関係

```text
Phase 2a (本部側実装)
     │
     └─→ Phase 2b (FC 加盟店側 POS 改修合意)
                                 │
                                 └─→ Phase 3 (紙廃止判断)
```

Phase 2a が phase 2b に先立つ理由は:

- POS 仕様の帳票並列出力の**非破壊性**を事前検証しておく必要が
  ある
- FC 加盟店側の実装負担の見積もりを示すことで、fee 分担を減少
  できる
- 負担に偏りが生じた場合の fee 再配分の交渉条件を先に確定させる

## 8 KPI 定義 (紙廃止判断ライン)

| KPI | 目標 | 条件 |
| --- | --- | --- |
| 提示操作数 | 1 回 | 決済 ID = 会員 ID |
| opt-in 率 (段階 1) | 60% | 局所上限到達 |
| opt-in 率 (段階 2) | 95% | 紙廃止の必須条件 |

**opt-in 率 95% に達しない限り紙レシートの廃止を禁止する。**
紙レシートと電子レシートの二重運用を原則とする。

## 9 リスクと緩和策

| リスク | 緩和策 |
| --- | --- |
| FC 加盟店側の POS 改修拒否 | 帳票並列出力追加のみの最小改修。fee 配分の事前合意 |
| opt-in 率が伸びない | 決済 ID = 会員 ID の統合で負担を 1 操作に |
| 二重インフラの固定費 | opt-in 率向上後、段階的に紙を後退させる |
| 本部側のデータ搬出拒否 | センターを中立ゲートにし、本部側の自社アプリ集約を維持 |
| 現金決済の ID 取得 | 会員提示型 opt-in を認め、紙と並行を原則 |
| JDLA スキーマ解釈の差異 | センター側で正規化層を追加 |

## 10 結論と推奨

ユーザーの仮説「コンビニの電子レシート導入はそう難しいものでも
ないはず」は技術的には**ほぼ正しい**。既存資産 (会員アプリ・決
済・ポイント・規約ベースの購入履歴) を用い、1〜3 か月で実装可能
な範囲にある。

ただし、**「実装が容易」は「紙が消えること」を意味しない**。即
効性のある普及のための条件は以下のようになる。

1. **決済 ID = 会員 ID** を前提とした UX (提示 1 回)
2. **FC 加盟店側の POS 改修の fee 配分**を本部側の意図から先に
   分解し、契約構造を事前に解決する
3. **紙の廃止判断**を opt-in 率 95% という段階的基準にバインドす
   る

**推奨**: Phase 2a (本部側技術) と Phase 2b (FC 加盟店合意) を
別 ADR か、あるいは本 ADR の下位粒度として明示で分解した上で次
の意思決定に進むこと。以後の判断は ADR-001 側に従う。
