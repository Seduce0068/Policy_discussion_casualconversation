## 1. 提言の概要

### 1.1 問題認識

日本企業における生成AIの導入では、技術的な安全性とは別に、取引先との契約や社内規則によって利用が禁止される問題がある。

特に、受注側企業が発注側企業よりも取引上弱い立場にある場合、発注側の保守的な判断が、そのままサプライチェーン全体に適用される構造が生まれる。

この場合、禁止の合理性や技術的な必要性が検証されないまま、受注企業やそこで働く労働者がAIを利用できなくなる。

問題は単なる企業ごとのセキュリティ方針の違いではない。

- 安全性の評価基準が統一されていない。
- 個々の企業が独自にAIサービスの安全性を判断しなければならない。
- 取引先ごとに利用許可を取得する必要が生じる。
- 取引上の力関係によって合理的でない禁止が受け入れられる。
- 禁止による生産性低下の負担が、主に受注側と労働者に転嫁される。

これらを解決するには、政府による安全性認定と、根拠のない利用禁止契約を無効化する法制度が必要である。

### 1.2 政策の基本原則

本提言の中心原則は次のとおり。

国が認定したエンタープライズAIサービスについて、認定条件内の標準的な業務利用を原則として認める。利用を禁止する側には、具体的な合理的根拠と必要性の立証を求める。

単にAI利用を推奨するのではなく、不合理な禁止契約そのものに法的な制限を設けることを目指す。

## 2. 問題の構造

### 2.1 取引上の優越的地位による禁止の連鎖

例えば、次のような取引構造を考える。

1. 大手発注企業が生成AIの全面禁止を決定する。
2. 受注企業は取引を失うことを恐れて禁止条項を受け入れる。
3. 受注企業は自社の従業員にもAI利用を禁止する。
4. その従業員が担当する業務では、生産性向上の手段が失われる。
5. 他の取引先でも同様の禁止が繰り返される。

この構造では、最初の発注企業が設定した制限が、実際のリスク評価を経ずに複数の企業へ波及する。

特にSES、システム開発、業務委託など、多重の取引関係がある業界では影響が広がりやすい。

### 2.2 禁止する側と禁止される側の負担の非対称性

| 項目 | 禁止する側 | 禁止される側 |
| --- | --- | --- |
| 利用禁止の決定 | 主導できる | 原則として従う |
| 禁止の合理性の検証 | 必ずしも実施しない | 説明を求めにくい |
| 生産性低下 | 間接的な影響 | 直接的な影響 |
| AI導入の機会損失 | 組織全体に分散 | 個々の業務に集中 |
| 取引継続の交渉力 | 強い場合がある | 弱い場合がある |

禁止によって利益を受ける側と、コストを負担する側が一致していない。

そのため、契約自由だけに任せると、合理性の低い禁止が維持される可能性がある。

## 3. 外部クラウド・エンタープライズAIの安全性評価

### 3.1 外部クラウド利用を一律に危険と扱わない

外部クラウドを利用することと、情報を無制限に第三者へ提供することは同義ではない。

例えば、個人情報保護委員会のFAQでは、クラウド事業者が個人データを取り扱わない契約・アクセス制御の条件を満たす場合、個人データの第三者提供にも委託にも該当しないケースが示されている。

参考：[個人情報保護委員会・クラウドサービス利用に関するFAQ Q7-53](https://www.ppc.go.jp/all_faq_index/faq1-q7-53/)

したがって、クラウドを利用するという事実だけで、法律違反や情報漏えいの危険性を断定することはできない。

ただし、生成AIサービスでは、入力データの処理、保存、学習利用、ログ管理、外部連携、再委託などを個別に評価する必要がある。

### 3.2 リスク評価の対象

| リスク | 確認事項 |
| --- | --- |
| 学習への流用 | 入力データが汎用モデルの学習に使われるか |
| 不正アクセス | 外部攻撃による情報取得の可能性 |
| 内部不正 | サービス提供者の従業員による不正利用 |
| テナント間漏えい | 他の利用者へのデータ露出 |
| 再委託 | 再委託先とデータ処理経路 |
| データ所在地 | 保存・処理地域と適用法令 |
| 権限逸脱 | AIエージェントによる過剰なアクセス |
| ログ・保持 | 入力内容や生成結果の保存期間 |

これらのリスクは、それぞれ異なる発生条件と対策を持つ。

一律禁止ではなく、具体的なリスクと対策の対応関係を評価するべきである。

### 3.3 発生確率と期待損失

リスク評価では、次の考え方を採用する。

期待損失 ＝ 発生確率 × 発生時の損害額

さらに、次の要素を考慮する。

- 事故の発生頻度
- 事故発生時の影響範囲
- 損害の回復可能性
- 既存の安全対策によるリスク低減
- 禁止した場合の生産性損失
- 禁止によってシャドーAIが増える可能性

なお、現状ではエンタープライズAIの利用回数を分母とした、信頼性の高い情報漏えい発生確率の公的統計は不足している。

発生確率が不明であることを、危険性が高いことの証明として扱ってはならない。

重大な影響が想定される場合には、低頻度でも制限を認め得るが、その場合も対象データと制限範囲を具体化する必要がある。

## 4. 国によるエンタープライズAI認定制度

### 4.1 制度の目的

政府が一定のセキュリティ基準を定め、条件を満たしたエンタープライズAIサービスを認定・公開する。

これにより、各企業が個別に安全性をゼロから判断する負担を軽減する。

### 4.2 認定基準

| 評価項目 | 要求事項 |
| --- | --- |
| 学習利用 | 入力データの汎用モデル学習への利用を制御 |
| データ保持 | 保存期間と削除条件の明確化 |
| 暗号化 | 通信時・保存時の適切な暗号化 |
| テナント分離 | 利用企業間のデータ分離 |
| 認証 | 多要素認証、権限管理 |
| 監査 | 操作ログ、アクセス履歴 |
| 再委託 | 再委託先の透明性と管理 |
| データ所在地 | 保存・処理地域の明示 |
| インシデント対応 | 検知、報告、復旧手順 |
| AI固有対策 | プロンプトインジェクション、情報漏えい、権限逸脱への対策 |
| 契約条件 | データ利用目的、責任範囲、削除義務の明確化 |

認定はサービス名だけではなく、契約プラン、構成、設定、利用条件を含めて行う。

同一事業者の個人向けサービスとエンタープライズサービスを同じものとして扱わない。

### 4.3 既存制度との関係

既存のISMAPは、政府が求めるセキュリティ要求を満たすクラウドサービスを評価・登録する制度である。

ただし、ISMAP登録済みの基盤を利用しているだけで、生成AIサービス自体の安全性まで保証されるわけではない。

したがって、既存制度を活用しつつ、生成AI固有の評価を追加する必要がある。

参考：[ISMAP・生成AIサービスに関する留意点](https://www.ismap.go.jp/)

## 5. 不当なAI利用禁止契約の無効化

### 5.1 基本方針

認定されたエンタープライズAIについて、認定条件内の標準的な業務利用を全面的に禁止する契約条項は、合理的な根拠がない場合に無効とする。

ここで重要なのは、禁止条項の存在自体を無条件に否定することではない。

禁止の必要性を説明できない条項に、法的効力を与えないことである。

### 5.2 立法案の骨子

#### 第1条：標準利用の原則

国が認定したエンタープライズAIサービスについて、認定条件および標準利用条件の範囲内で行う業務利用を原則として認める。

#### 第2条：不当な利用制限条項の無効

合理的な理由なく、認定サービスの標準利用を一律に禁止する契約条項は無効とする。

#### 第3条：禁止理由の立証

利用禁止を求める当事者は、以下を客観的に説明しなければならない。

1. 禁止対象となるデータまたは業務。
2. 想定される具体的なリスク。
3. 認定サービスの対策では不十分となる理由。
4. リスクの発生可能性と影響。
5. より限定的な代替策では不十分となる理由。

#### 第4条：比例原則

禁止は、具体的なリスクを低減するために必要な範囲に限定する。

特定の顧客情報の入力禁止を、AIサービス全体の利用禁止に拡大してはならない。

#### 第5条：報復的取扱いの禁止

正当な理由なくAI利用制限の合理性を確認・争うことを理由として、取引停止、発注削減、契約更新拒否などの不利益を与える行為を規制する。

ただし、独立した合理的な経営判断による取引終了まで禁止しない。

### 5.3 無効化の対象範囲

対象とするのは、主として以下のような条項である。

- 認定サービスを一律に利用禁止とする条項。
- 外部クラウド利用を理由なく全面禁止する条項。
- AI利用を理由として受注企業に過剰な責任を負わせる条項。
- 具体的なリスクを特定せず、AI利用による損害を無制限に受注側へ転嫁する条項。
- 認定サービスの利用を事実上不可能にする不合理な追加条件。

なお、認定範囲外のサービス利用、無許可のデータ入力、アクセス権限違反などは別途評価する。

## 6. 既存法制度との接続

### 6.1 民法90条：公序良俗

公序良俗に反する法律行為は無効となる。

ただし、一般的なAI利用禁止条項が直ちに公序良俗違反になるわけではない。

AI利用制限の合理性を判断する明確な立法上の基準が必要である。

### 6.2 民法548条の2第2項：定型約款の不当条項

定型約款に含まれる条項で、相手方の利益を一方的に害するものは、一定の要件の下で合意されなかったものとみなされる。

ただし、この制度は定型約款を対象とするため、個別交渉で締結される企業間契約すべてに適用できるわけではない。

そのため、AI利用制限については別途明確な規定を設ける必要がある。

### 6.3 独占禁止法：優越的地位の濫用

公正取引委員会のガイドラインでは、相手方が取引継続の困難さから不利益な要請を受け入れざるを得ない状況を、優越的地位の判断要素としている。

大企業と中小企業の関係に限定されず、企業間の相対的な交渉力が考慮される。

参考：[公正取引委員会・優越的地位の濫用に関する独占禁止法上の考え方](https://www.jftc.go.jp/dk/guideline/unyoukijun/yuetsutekichii.html)

AI利用禁止を強制する行為についても、具体的な取引状況に応じて独占禁止法上の評価を行う余地がある。

### 6.4 取適法との関係

2026年1月1日には、下請法を改正した中小受託取引適正化法（取適法）が施行されている。

発注者と受注者の対等な取引関係を促進する既存の制度基盤として活用できる。

ただし、取適法の適用対象や禁止行為は法律上の要件に従うため、あらゆるAI利用禁止契約が当然に同法違反になるわけではない。

参考：[公正取引委員会・中小受託取引適正化法（取適法）](https://www.jftc.go.jp/partnership_package/toritekihou.html)

## 7. 労働者の保護

企業間契約の無効化だけでは、現場の労働者を十分に保護できない。

そのため、労働者に対する保護も必要になる。

### 7.1 不利益処分の制限

認定サービスを認定条件内で適切に利用したことのみを理由として、懲戒や不利益な人事処分を行うことを制限する。

ただし、会社の正当な業務命令や、認定条件を逸脱した利用に対する措置まで否定するものではない。

### 7.2 禁止理由の透明化

企業がAI利用を禁止する場合、少なくとも以下を明示する。

- 禁止対象のサービス。
- 禁止対象のデータ。
- 禁止対象の業務。
- 適用する法令・契約・セキュリティ要件。
- 禁止の具体的な理由。
- 再評価の時期。

### 7.3 異議申立て

労働者や受注企業が、禁止理由の合理性について第三者に相談・審査を求められる制度を設ける。

## 8. 制度の実装方法

### 第1段階：認定基準の策定

経済産業省、総務省、個人情報保護委員会、IPAなどが連携し、生成AIサービスの評価基準を整備する。

### 第2段階：認定サービスの公開

認定対象について、以下を公開する。

- サービス名と契約プラン。
- 認定された構成。
- データの処理条件。
- 利用可能なデータ区分。
- 認定の有効期間。
- 認定条件の変更履歴。

### 第3段階：標準契約条項の整備

発注企業と受注企業が共通して利用できるAI利用条項を公開する。

これにより、企業ごとの個別交渉を減らす。

### 第4段階：法的効力の付与

認定サービスの標準利用を不合理に制限する条項について、無効化の規定を整備する。

### 第5段階：監督・救済制度

公正取引委員会などの既存機関との役割分担を明確にし、相談、調査、是正、紛争解決の仕組みを設ける。

## 9. 想定される反対意見と対応

| 反対意見 | 対応 |
| --- | --- |
| 企業には契約自由がある | 契約自由にも合理的な制約を設ける既存の法体系がある |
| 情報漏えいが怖い | サービスとデータの具体的なリスク評価を行う |
| 取引先の秘密情報がある | 秘密情報の分類と必要な保護措置を設ける |
| 海外事業者は信用できない | 国籍ではなく処理条件・法的リスク・安全対策で判断する |
| 認定制度でも事故は起きる | 認定は無事故保証ではなく、リスク管理基準への適合を示す |
| 企業ごとに事情が異なる | 個別事情に応じた例外を認める |
| 認定基準が古くなる | 定期的な再評価と認定停止制度を設ける |

特に、認定制度は安全性の絶対保証ではない。

認定後に重大な脆弱性や契約条件の変更が判明した場合には、認定範囲の変更や停止を可能にする。

## 10. 期待される効果

### 10.1 AI導入コストの低減

取引先ごとにAIサービスの安全性を個別審査する負担を軽減できる。

### 10.2 中小企業の競争力向上

大企業と同じ認定サービスを利用できることで、企業規模によるAI活用能力の格差を縮小できる。

### 10.3 労働者の生産性向上

合理的な理由のないAI利用禁止によって、現場の業務改善が妨げられることを防止できる。

### 10.4 シャドーAIの抑制

正式に認定されたサービスを利用しやすくすることで、個人アカウントや無許可サービスへの流出を抑制できる。

### 10.5 サプライチェーン全体の効率化

共通の安全基準と標準契約を普及させることで、取引先ごとの重複した審査を減らせる。

## 11. 残された法制度上の検討事項

本提言を実際の立法にするには、以下の論点をさらに検討する必要がある。

1. 認定サービスの標準利用として保護する業務範囲。
2. 企業間契約における立証責任の具体的な配分。
3. 無効となる契約条項の定義と部分無効の扱い。
4. 取引停止・発注削減が報復に当たる場合の判断基準。
5. 労働者への懲戒・不利益処分に関する保護範囲。
6. 重大な事故が発生した場合の認定停止・再評価。
7. 既存の独占禁止法、取適法、個人情報保護法との整合性。
8. 行政による認定と民事上の契約効力の関係。

特に、単に「禁止条項は無効」と定めるだけでは、企業が別の契約条件や発注判断によって同じ制限を実現する可能性がある。

そのため、報復的な取引制限への対応も制度に含める必要がある。

## 12. 結論

本問題の本質は、エンタープライズAIの技術的な安全性だけではない。

安全性を客観的に評価する共通基準が不足しているため、個々の企業が独自の判断で利用を禁止でき、その判断が取引上の力関係によってサプライチェーン全体に強制されることにある。

その結果、禁止の合理性を検証する仕組みがないまま、AIの利用機会と生産性向上の利益が失われている。

この問題を解決するため、次の原則を制度化する。

第一に、国がエンタープライズAIサービスの安全基準を策定し、認定サービスを公開する。

第二に、認定条件内の標準的な業務利用を原則として認める。

第三に、合理的根拠のない利用禁止契約を無効とする。

第四に、利用禁止を求める側に具体的なリスクと必要性の説明を求める。

第五に、取引上の優越的地位を利用した禁止の強制や報復を防止する。

契約自由は、合理性のない制限を無条件に正当化するための原則ではない。

企業が情報を保護する権利を維持しながら、根拠のない禁止によって他社や労働者の業務改善手段を奪うことも防ぐべきである。

AIの安全性は、企業間の交渉力や保守的な慣習によって決定するのではなく、客観的な技術基準と合理的なリスク評価によって決定する。

これを日本の企業間取引における新しい標準とすることを提言する。
