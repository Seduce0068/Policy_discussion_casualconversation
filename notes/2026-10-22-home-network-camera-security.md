## 背景と目的

- 実家にネットワークカメラを設置する、または既に設置済みの環境を想定する。
- 目的は攻撃を完全に防ぐことではなく、家族が日常的に維持できる運用に落とすこと。
- 機器選定前の点検と、既存機器の設定見直しの双方に使える形にする。
- 技術対策より先に、誰が管理者になるか、何を守るかを決める。

## 前提と脅威モデル

### 守る対象

- カメラの映像と録画データ。
- 家庭内ネットワークにつながる端末（スマホ、PC、NAS、家電）。
- 家族のアカウント（メール、クラウド、カメラ、ルータ）。
- インターネット回線そのもの（踏み台化による停止や ISP からの注意喚起）。

### 主な侵入経路

| 脅威 | 現実的な経路 | 実家での影響 |
| --- | --- | --- |
| 機器への不正ログイン | 初期パスワード、使い回し、WAN 側の管理画面公開 | 映像ののぞき見、設定改ざん |
| マルウェア感染 | ファームウェアの既知脆弱性、EOL 機器 | 攻撃の踏み台、回線停止、ISP からの連絡 |
| クラウドアカウント乗っ取り | パスワード再利用、MFA 未設定、共有リンク | 映像の拡散、遠隔視聴 |
| ルータ経由の侵入 | UPnP による意図しないポート開放、WPS、古いファーム | 家庭内端末への横展開 |
| 人的被害 | フィッシング、サポート詐欺、遠隔操作ツール | 端末の乗っ取り、送金被害 |
| 物理・プライバシー | 盗難、近隣の映り込み、家族間の合意不足 | 信頼問題、法的リスク |

- 家庭用カメラの主経路は「インターネットに晒した管理画面」と「使い回しパスワード」。
- 映像そのものより、カメラがボットネットの一部になるリスクの方が実家では現実的。
- 対策の効き目は、機器の数ではなく「管理する入口の数」を減らすことで決まる。

## 対策の優先順位

### P0: 初回の訪問時に必ずやる

1. ルータ、カメラ、NAS、中継器の管理パスワードを個体別に変更する。
   Wi-Fi パスワードと管理用パスワードは別にする。
2. すべての機器のファームウェアを更新し、自動更新を有効にする。
3. ルータの WAN 側リモート管理、UPnP、WPS を無効にする。
4. カメラの共有リンクを全削除し、必要な共有は個別アカウントと期限付きに変える。
5. カメラとメールのアカウントで多要素認証（MFA）を有効にする。
6. メーカーのサポート終了（EOL）機器を洗い出し、交換計画を立てる。

- パスワードは 10 桁以上で英大文字小文字・数字・記号を含む。
  機器側の制約で記号が使えない場合は、入力可能な最大桁数と文字種を使う。
- 初期パスワードが個体別に設定されている近年の機器でも、管理画面の公開範囲は確認する。

### P1: 1 か月以内

- メイン SSID と IoT 用 SSID を分離し、IoT 側から LAN に届かないことを実機で確認する。
- ルータの接続機器一覧を月 1 回見る手順を作り、見覚えのない機器を検出できるようにする。
- 録画データの保存先、保存期間、暗号化の有無を決める。
- 家族の役割を決める（管理者、閲覧者、緊急時の連絡先）。

### P2: 買い替え・更新時

- 端末設備等規則第 34 条の 10 の 4 要件を満たす製品を選ぶ。
- IPA の JC-STAR ★1 ラベルを最低条件にし、カメラは上位区分の動向も確認する。
- 自動更新の有無、サポート期限、クラウド終了時のローカル録画可否を確認する。

## ルータの設定

| 項目 | 推奨 | 理由 |
| --- | --- | --- |
| 管理パスワード | 個体別・16 桁以上・使い回し禁止 | 初期値はマニュアルや Web に公開されている |
| ファームウェア | 自動更新 ON、月 1 で版を確認 | 既知脆弱性の修正を遅らせない |
| WAN 側リモート管理 | OFF | インターネットからの管理画面露出を断つ |
| UPnP | OFF（必要なら個別にポート転送） | 意図しないポート開放を防ぐ |
| WPS | OFF | PIN 方式の総当たりやボタン悪用を防ぐ |
| 無線暗号 | WPA3-SAE または WPA2-AES | WEP と TKIP は突破可能 |
| SSID | メインと IoT を分離 | カメラ侵害時の横展開を抑える |
| 接続機器一覧 | 月 1 で確認 | 見覚えのない機器の検出 |

- UPnP を切るとゲーム機、NAS、一部家電の自動検出が壊れる。
  家族の利用を確認し、必要な機器だけ個別にポート転送する。
- ドコモ HOME 5G のような CGNAT 環境でも、UPnP や P2P で穴が開くことがある。
  「外部から届かないはず」と過信しない。
- ルータの設定画面を外部に公開する機能がある場合、使わないなら必ず切る。

## セキュアバイデフォルトの難しさ

- 実装より、デフォルトを安全側に倒すと既存の利便性とサポート体制が壊れる点が難しい。
- 技術・経済・運用・制度の 4 層で問題が連鎖する。

### 難しさの層

- 互換性: UPnP、WPS、WAN 側リモート管理を OFF にすると、ゲーム機、NAS、
  遠隔サポート、カメラの自動設定が壊れる。メーカーは返品と問い合わせを恐れる。
- ストックとフロー: デフォルト変更は新規出荷にしか効かない。既設置機器は
  初期化しない限り変わらず、「新規は安全、既存は不安全」が長期併存する。
- 管理者の不在: 家庭に管理者はいない。ISP 提供機器は ISP と利用者の二重管理になり、
  責任分界が曖昧になる。
- 更新の原資: 低価格帯はファーム更新の原資が薄く EOL も早い。
  更新が止まればデフォルトの安全も維持できない。
- 規制の粒度: 端末設備等規則第 34 条の 10 は変更を促す範囲に留まり、
  検証と罰則が弱い。JC-STAR は市場誘導であり、調達・小売・ISP の
  インセンティブが要る。

### 成立する条件

1. 出荷時に閉じる。WAN 管理、UPnP、WPS は OFF、管理パスワードは個体別。
2. 必要時だけ開ける。ポート転送は明示操作、期限、一覧表示を伴う。
3. 自動更新を既定にし、失敗時はロールバックする。
4. 設定ミスで締め出されない復旧手段を用意する。
5. 接続機器一覧、設定変更通知、不審ログイン通知を標準で持つ。

- デフォルトで安全と、侵害されないは別。パッチ供給と EOL 管理がなければ、
  デフォルトは入口を狭めるだけに留まる。
- 既設機器はデフォルトに期待できないため、訪問時の 4 点チェックで補う。
- 買い替え時は「デフォルトが閉じているか」を仕様として確認する。

## ネットワークカメラの設定

| 項目 | 推奨 |
| --- | --- |
| 管理パスワード | 個体別に変更。初期値のままにしない |
| ファームウェア | 自動更新 ON。EOL を定期的に確認 |
| クラウドアカウント | 家族ごとに個別作成。MFA を有効化 |
| 権限 | 管理者と閲覧のみを分ける。共有アカウントを避ける |
| 共有リンク | 期限付き。視聴が終わったら削除 |
| 外部公開 | ポート開放しない。HTTP、RTSP、ONVIF を WAN に出さない |
| リモート視聴 | メーカークラウドか VPN 経由。DDNS とポート開放の組合せは避ける |
| 録画 | microSD か NAS。暗号化と保存期間を決める |
| 物理 | 高所に固定し、配線を隠す。LED とレンズの向きを確認 |

- クラウド型のカメラはポート開放が不要な代わりに、アカウント保護が生命線になる。
- ローカル録画はクラウド停止や値上げに強いが、NAS 自体の更新とアカウント管理が増える。
- 録画映像に本人が判別できる形で映る場合、事業者にとっては個人情報に該当する。
  家庭内利用は事業者規制の対象外だが、近隣を撮る場合は肖像権とプライバシーへの配慮が必要。
- 浴室、脱衣所、寝室、子ども部屋は監視対象にしない。
  玄関や庭でも、近隣の窓や道路を映さない向きにする。
- カメラの存在を家族と来訪者に分かるようにし、必要なら「防犯カメラ作動中」と掲示する。

## アカウント設計

- メールアカウントを最優先で守る。パスワード再設定の起点になるため。
- 管理者は 1 人に固定し、閲覧者は個別アカウントにする。
- 共有アカウントは使わない。やむを得ない場合も MFA とパスワード管理を徹底する。
- パスワードマネージャで家族用の保管庫を作り、緊急時のアクセス手順を決める。
- 使っていない共有ユーザー、API キー、連携アプリを半年ごとに棚卸しする。
- 不審なログイン通知を有効にし、通知先を管理者のスマホにする。

## 実家で維持できる運用

- 本人が設定を維持できない前提に立ち、設定項目を増やさない。
- 変更は訪問時か遠隔サポートに限定し、変更履歴を 1 枚のメモに残す。
- ラベルには管理 URL、SSID、管理者名、変更日だけを書き、パスワードは書かない。
- 停電、初期化、機種変更の復旧手順を家族が読める形で残す。
- 「見守りの範囲」「誰が見るか」「費用負担」「やめる条件」を家族で決める。
- 定期的な見直しは月 1 の機器確認と、半年ごとのアカウント棚卸しの 2 段階にする。

## 監視とインシデント対応

- 月 1 回、接続機器一覧、ファームウェアの版、共有リンク、不審ログイン通知を確認する。
- 次の兆候があれば侵害を疑う。
  - カメラの向きや設定が変わっている。
  - 身に覚えのない視聴通知やログイン通知が届く。
  - 通信量が急に増える、回線が不安定になる。
  - ISP や NOTICE から注意喚起が届く。
- 疑わしい場合は、初期化、ファームウェア更新、パスワード変更、共有リンク削除、
  ログ確認の順で対応し、必要なら ISP とメーカーに相談する。
- 不注意な初期化は録画データを失う。可能なら設定変更前にバックアップを取る。

## 購入・更新の判断基準

- 端末設備等規則第 34 条の 10 が求める 4 要件を満たす。
  - 不正な設定変更を防ぐアクセス制御機能がある。
  - 初期設定から ID・パスワードの変更を促す、または個体別の ID・パスワードがある。
  - ファームウェアを更新できる。
  - 電源を切っても ID・パスワードとファームウェアが初期化されない。
- JC-STAR の適合ラベルがある。
- 自動更新が提供され、サポート期限が明示されている。
- クラウドサービス終了後もローカル録画や基本機能が残る。
- 家族が設定を理解できる複雑さに収まっている。

## 見解

- 最初に投資すべきはカメラの高機能化ではなく、ルータとアカウントの基本対策。
- 実家では、設定項目を増やす対策は時間とともに劣化する。
  自動更新、クラウド、個体別パスワード、SSID 分離の 4 点に寄せる。
- ポート開放によるリモート視聴は避ける。必要な場合はメーカークラウドか VPN にする。
- 映像のプライバシーは技術対策より、合意と設置位置で決まる。
- 次の訪問でやることは、パスワード変更、ファームウェア更新、UPnP・WPS・遠隔管理の無効化、
  共有リンク削除の 4 点。これだけで主要な経路はかなり塞げる。

## 確認したいこと

- カメラのメーカー、型番、台数。クラウド型かローカル録画型か。
- ルータのメーカー、型番、回線種別。設定画面でどこまで変更できるか。
- 外出先から見たいか。見るのは誰か。共有したい相手はいるか。
- 録画は microSD、NAS、クラウドのどれか。保存期間の希望。
- 家族に管理者を引き受けられる人がいるか。緊急時の連絡先。
