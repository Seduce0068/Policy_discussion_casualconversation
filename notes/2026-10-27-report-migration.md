## 現行フロー

- システムが Excel を生成する。
- 業務担当が Excel を開き、必要なら編集する。
- 業務担当が PDF として出力する。
- PDF を帳票として利用する。

Excel が「帳票テンプレート」と「データ」の両方の役割を持ち、
PDF 出力が業務側の手作業になっている。

## 課題

- 業務側の手作業が発生し、自動化できない。
- PDF の内容が、業務側の Excel のバージョン、フォント、プリンタに依存する。
- システムが PDF の内容を保証できない。
- 大量出力に向かない。
- 電子帳簿保存法の真実性（誰が、いつ、何を出力したか）を満たしにくい。
- Excel のマクロや数式が業務ロジックの一部になっている可能性がある。

## 移行後の選択肢

| 方式 | 内容 | 長所 | 短所 | 適用条件 |
| --- | --- | --- | --- | --- |
| 現状維持 | Excel 生成と業務側の PDF 出力を続ける | 変更が小さい | 手作業と環境依存が残る | 移行期のみ |
| 直接 PDF 生成 | システムが PDF を生成する | 自動化、内容保証、大量出力 | レイアウトの再現が必要 | 編集不要の定型帳票 |
| Excel テンプレート + PDF 生成 | Excel テンプレートにデータを埋め、PDF に変換する | Excel 資産を活かせる | 変換環境とレイアウトの検証が必要 | 編集必要の定型帳票 |
| Web 帳票 + PDF | 画面でプレビューし、PDF をダウンロードする | 編集と確認が Web で完結 | 画面開発が必要 | 編集必要の非定型帳票 |

## 推奨

- 帳票を「編集不要」「編集必要・定型」「編集必要・非定型」に分類する。
- 編集不要の定型帳票は、システムが直接 PDF を生成する。Excel は廃止する。
- 編集必要の定型帳票は、Excel テンプレートを維持し、システムが PDF に変換する。
- 編集必要の非定型帳票は、Web の編集画面と PDF ダウンロードに移行する。
- 現状維持は移行期だけとし、最終的には Excel の手作業をなくす。
- Excel を「正」にしない。帳票定義とテンプレートをテキストで管理する。

## 技術選定

| 用途 | 推奨 | 代替 | 備考 |
| --- | --- | --- | --- |
| 複雑な帳票 | JasperReports | BIRT | バンド、集計、サブレポート |
| シンプルな PDF | OpenPDF | PDFBox | レイアウトをコードで制御 |
| HTML ベースの帳票 | Thymeleaf + Flying Saucer | OpenHTMLtoPDF | CSS でレイアウト |
| Excel 生成 | Apache POI | JXLS | テンプレートにデータを埋める |
| Excel → PDF | LibreOffice headless | Aspose.Cells | サーバーに LibreOffice が必要 |
| PDF プレビュー | PDF.js | ブラウザ標準 | Web 画面に埋め込む |
| PDF 検証 | PDFBox | 画像比較 | テキスト抽出とスナップショット |

## テスト

- PDF のスナップショットを比較する。フォントと埋め込みで差分が出るため、許容差を設定する。
- PDFBox でテキストを抽出し、記載事項を確認する。
- フォントが埋め込まれているか確認する。
- 改ページ、ヘッダ、フッタ、ページ番号を確認する。
- 大量出力の性能を確認する。
- 電子帳簿保存法とインボイス制度の記載事項を確認する。

## リスク

| リスク | 影響 | 対策 |
| --- | --- | --- |
| レイアウト崩れ | 帳票の再利用不可 | PDF のスナップショット比較 |
| フォント差異 | 文字化け、改行位置のずれ | フォントを埋め込む |
| マクロ依存 | 業務ロジックの移行漏れ | マクロを棚卸し、コードへ移す |
| 電子帳簿保存法 | 監査対応の不備 | タイムスタンプ、訂正履歴を確認 |
| インボイス制度 | 記載事項の不足 | 適格請求書の要件を確認 |
| 編集機能の喪失 | 業務の手戻り | 編集が必要な帳票を先に分類する |

## QA に出す条件

- 業務側の編集が必要か。
- 編集は承認プロセスに組み込まれているか。
- 法的な保存要件は何か。
- 配布方法はメール、郵送、ポータルのどれか。
- 印刷や押印が必要か。
- Excel のマクロや数式が業務ロジックになっているか。
